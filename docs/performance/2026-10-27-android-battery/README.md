# Расход батареи Android: исходные данные 2026-10-27

Измерена Carlitos **1.0.8**, коммит `07426df1602be16061a75da080e486f39fa90af7`, на Xiaomi MI Max 3,
Android 13 / LineageOS. Использован оптимизированный ARM64 release APK.
Четыре режима по четыре минуты и контроль с остановленным приложением.
Все строки прошли проверку питания, состояния экрана, медиасессии и процесса.

| Режим | Время, с | Заряд, мА·ч | Средний ток телефона, мА | CPU Carlitos, % одного ядра |
| --- | ---: | ---: | ---: | ---: |
| Пауза, экран включён | 240.9 | 21.075 | 315.0 | 0.14 |
| Воспроизведение, экран включён | 240.8 | 39.073 | 584.1 | 82.85 |
| Воспроизведение, экран выключен | 241.1 | 6.409 | 95.7 | 21.46 |
| Пауза, экран выключен | 245.8 | 2.703 | 39.6 | 0.04 |
| Приложение остановлено, экран выключен | 243.2 | 2.646 | 39.2 | 0.00 |

Это расход **всего телефона**, вычисленный из изменения аппаратного счётчика
заряда. Единица мА также соответствует мА·ч за час при постоянной нагрузке.
Значения не являются точной оценкой энергии, относящейся только к Carlitos.
Целочисленный процент заряда оставлен в сырых данных для контекста; результат
не вычислялся по разнице процентов и не экстраполировался в часы автономности.

## Условия

- Экран 1080×2160, ручная яркость 255/255; зарядка отключена.
- Wi-Fi ADB оставался подключён; запрос показаний каждые 15 секунд.
- Библиотека с одной синтетической книгой, тёмная тема, анимированный фон включён,
  уменьшение анимаций выключено, локальная синхронизация выключена.
- Локальный MP3: 64 кбит/с, 32 кГц, стерео, 30 минут, скорость 1×,
  пропуск тишины выключен. Источник — повторённый тестовый тон из репозитория.
- Системная громкость оставлена 0/25. Замер включает воспроизведение и обработку
  аудио, но не характеризует обычное прослушивание на ненулевой громкости.
  Внутренняя громкость плеера 0,7; AudioTrack действительно активен, маршрут —
  динамик. AudioFlinger преобразует 32 кГц стерео PCM в выходные 48 кГц PCM.
- Перед каждым режимом 20 секунд стабилизации; перед остановленным контролем
  45 секунд. Статистика Android не сбрасывалась.
- Порядок: пауза с экраном → воспроизведение с экраном → воспроизведение без
  экрана → пауза без экрана → остановленный процесс без экрана.
  Между вторым и третьим режимом была диагностическая пауза: первоначальная
  проверка требовала `Asleep`, а прошивка при физическом `OFF` сообщает `Dozing`.
  Единичная пробная запись исключена; третий режим полностью измерен заново
  с прямой проверкой `mScreenState=OFF` в каждой точке.

## Сравнение для будущей оптимизации

Наблюдаемая разница среднего тока всего устройства:

- Воспроизведение против паузы при включённом экране:
  +269.1 мА.
- Воспроизведение против паузы при выключенном экране:
  +56.1 мА.
- Пауза без экрана против остановленного приложения:
  +0.4 мА.

Это последовательные одиночные измерения. Разницы включают шум фоновой нагрузки,
изменения температуры и влияние порядка; они не доказывают причинность и не
задают статистически значимый порог улучшения. Для проверки небольшого изменения
повторить исходную и изменённую сборки несколько раз, чередуя порядок.

Самые занятые потоки приложения по диагностическим срезам:

Для следующего профилирования сравнить видимый интерфейс при воспроизведении с
отключёнными анимациями и с текущими настройками, затем отдельно проверить аудио
с погашенным экраном. Данные потоков показывают место нагрузки, но не заменяют
профиль стека и не доказывают причину. Синтетический постоянный тон не повторяет
все изменения спектра речи. Включённая локальная синхронизация, другие кодеки,
скорости воспроизведения и Bluetooth в этом замере не проверялись.

## Метод и ограничения

`dumpsys battery` возвращал запаздывающее значение `Charge counter`. Для итогового
набора применены прямые запросы Android 13 `IBatteryPropertiesRegistrar.getProperty`
через `service call batteryproperties 1 i32 1` (заряд) и `i32 2` (мгновенный ток).
Ответы проверялись на успешный статус; знаковое 64-битное поле Parcel разбиралось
как значение в мкА·ч либо мкА. Предварительный прерванный замер по кешированному
счётчику исключён из этого набора.

Формулы:

```text
расход_мАч = (заряд_начало_мкАч − заряд_конец_мкАч) / 1000
средний_ток_мА = расход_мАч × 3600 / время_с
CPU_% = Δ(utime + stime) / CLK_TCK / время_с × 100
```

Время берётся из `/proc/uptime`. CPU нормирован на одно ядро, не на все восемь.
В `summary.json` дополнительно сохранены линейный наклон ряда заряда, среднее и
медиана выборки мгновенного тока, CPU системных процессов, CPU потоков приложения
и задержки ADB-запросов. Мгновенный ток читается во время запроса ADB и может
отражать пробуждение от самого запроса; основной результат рассчитан по заряду
за целый интервал. В режиме паузы без экрана задержки ответов достигали нескольких
секунд. Из-за задержек реальное время интервала может отличаться от заданных
240 секунд; в формулах использовано измеренное время.
Срезы потоков чуть шире основного интервала из-за последовательного снятия дампов;
они служат диагностике, а не точному разделению энергии по компонентам.

На этой прошивке `batterystats` показывает `cpu=0` и `audio=0` даже при учтённом
процессорном времени и воспроизведении. Поэтому его оценка мА·ч для UID приложения
не использована как измерение расхода Carlitos. Аппаратные energy-consumer counters
в отчёте Android не поддерживаются.

Wi-Fi ADB и регулярные запросы создают собственную нагрузку и пробуждения. Экран
проверялся по `mScreenState=OFF`; `mWakefulness=Dozing` допускается, если сам
дисплей выключен. Это не доказывает глубокий сон CPU. Эти данные
подходят для сравнения одинаковых условий; они не заменяют длительный тест
ожидания без ADB. Ток зависит от датчика телефона; внешний измеритель не применялся.

## Файлы и повторение

- [summary.json](summary.json) — результаты режимов и дополнительные показатели.
- [samples.csv](samples.csv) — ряд заряда, тока, экрана и состояния плеера.
- [samples.jsonl](samples.jsonl) — те же записи, CPU процессов и удержания бодрствования.
- [metadata.json](metadata.json) — версия, хеши APK и условия.
- [capture.py](capture.py) — использованный сборщик для Android 13.

Поле `media_position_ms` — позиция, сообщённая MediaSession; она может быть
якорем для системной экстраполяции по времени и скорости. Её неизменность между
запросами сама по себе не означает остановку: состояние воспроизведения хранится
в `media_state`, а активный AudioTrack отдельно подтверждён дампом AudioFlinger.

При замере APK, резервная копия старых данных и полные дампы сохранялись в
`target/battery/20261027T182220Z/`, за пределами Git. При очистке старых сборок
резервные данные и архив текстовых дампов перенесены в локальный закрытый каталог
`.codex/backups/android-battery-20261027/` основной рабочей копии; старые APK и
сгенерированный длинный MP3 удалены. Актуальные APK 1.0.8 сохранены в `target/releases`.
Для обновления без удаления данных тестовая копия подписана прежним Android debug
ключом: содержимое APK вне подписей проверено на полное совпадение с релизом.
Production APK не переподписывался. После замера приложение остановлено, экран погашен, таймаут экрана
восстановлен. Тестовая книга оставлена для повторных измерений.

Перед повторением выбрать ту же книгу, убедиться, что устройство разблокировано,
и использовать новый каталог результатов. Скрипт не устанавливает приложение и
не сбрасывает статистику, но включает/выключает экран, управляет медиасессией и
в конце принудительно останавливает указанный пакет. На телефоне не должно быть
других активных медиаплееров. Значения яркости и громкости выставить как выше.

```sh
python3 docs/performance/2026-10-27-android-battery/capture.py \
  --adb "$ANDROID_HOME/platform-tools/adb" --serial "$ANDROID_SERIAL" \
  --duration 240 --interval 15 --settle 20 \
  --output target/battery/repeat-01
```

Тестовый файл можно воспроизвести без перекодирования:

```sh
ffmpeg -stream_loop -1 -i tests/fixtures/import-stereo.mp3 -t 1800 \
  -map 0:a:0 -c:a copy -metadata 'title=Carlitos battery benchmark' \
  -metadata 'artist=Local synthetic test fixture' carlitos-battery-benchmark.mp3
```

Единицы и свойства датчика описаны в [Android BatteryManager](https://developer.android.com/reference/android/os/BatteryManager).
Ограничения аппаратных датчиков — в [AOSP: Measure device power](https://source.android.com/docs/core/power/device).
Модельные оценки `batterystats` — в [AOSP: Power profiles](https://source.android.com/docs/core/power).
