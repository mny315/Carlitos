# Carlitos для Android

Локальные аудиокниги, импорт файлов и папок, сохранение позиции и фоновое
воспроизведение. Android 8.0+, ARM 64 бита (`arm64-v8a`) и ARM 32 бита
(`armeabi-v7a`), OpenGL ES 3.

При первом запуске приложение предлагает отключить для него оптимизацию батареи
через системное окно Android. После отказа запрос автоматически не повторяется;
открыть его снова можно через «Настройки → Фоновая работа». Если исключение уже
включено, эта кнопка открывает системные настройки оптимизации батареи.
На прошивках без такого окна приложение открывает список оптимизации батареи
или сведения о приложении. Фоновое воспроизведение использует медиасервис
с уведомлением; исключение из оптимизации не защищает от принудительной остановки
или всех дополнительных ограничений производителя телефона.

Из корня проекта на Linux с Nix:

```sh
./build.sh android keygen  # создать собственный ключ один раз
./build.sh android         # подписанный релиз с оптимизированной Rust-библиотекой
./build.sh android debug   # отладочный APK
./build.sh android install # сборка и установка отладочного APK через ADB
./build.sh android run     # сборка, установка и запуск отладочной версии
./build.sh android devices
./build.sh check android
./build.sh test android ui
```

Релизы в `target/releases/`, каждый со своим файлом SHA-256:

- `Carlitos-1.0.1-android-armeabi-v7a-release.apk` — ARM 32 бита (v7).
- `Carlitos-1.0.1-android-arm64-v8a-release.apk` — ARM 64 бита (v8).
- `Carlitos-1.0.1-android-universal-release.apk` — обе архитектуры в одном APK.

Если архитектура телефона неизвестна, используйте универсальный APK:
Android выберет подходящую библиотеку. Отладочная сборка создаёт те же три
варианта; команды установки и тестов используют универсальный APK.
`./build.sh check android` проверяет Rust-код для обеих архитектур.
Первая ARM32-сборка компилирует Skia из исходников и занимает больше времени;
Nix-окружение включает необходимые GN и Ninja.
Перед копированием релизного APK сборка проверяет его подпись через `apksigner`.
Логи: `target/logs/android-release.log` (или `android-default.log` для команды
без подкоманды), `target/logs/test-android-ui.log` и аналогичные для других групп.
Каждый новый запуск перезаписывает лог соответствующей команды.

Ключ RSA-4096 хранится в `.secrets/android/release.p12`, настройки и случайный
пароль — в `.secrets/android/signing.properties`. Каталог доступен только
владельцу и исключён из Git. Повторная генерация не заменяет существующий ключ.
Сохраните защищённую резервную копию всего `.secrets/android/`; не удаляйте его
при очистке сборок. Отсутствующий ключ приводит к ошибке релизной сборки.

Релизная подпись отличается от прежней отладочной: Android не установит новый
APK поверх старого debug APK с тем же идентификатором. Переустановка с удалением
старой версии удаляет её локальные данные; сохраните нужные данные заранее.
Последующие релизные APK, подписанные этим ключом, обновляются обычным способом.

Для нескольких ADB-устройств задайте `ANDROID_SERIAL`.
Версии инструментов закреплены в `nix/android-versions.json`.
Номер версии берётся из `Cargo.toml`; `versionCode` повышается в `app/build.gradle`.
Устройство не требуется для сборки APK. Тесты и их manifest находятся в
`tests/android/`, тестовые JNI-функции — в `src/android/tests/` и не входят в релиз.
